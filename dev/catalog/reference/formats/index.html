    File formats¶

    This page lists every key the catalog's files use. The formats are defined by the document types in contracts/, and CI checks every file against them. Where this page and the schema source disagree, the schema is right.

    Three conventions hold across the files:

    • A file's name is its identity, except for model.yaml, which states its name and must match its directory. A name key in a chip, fabric or workload file is rejected.
    • Unknown keys are errors. The exception is a comment key: _comment, or a key that begins with _comment_. Comment keys hold the provenance prose and are ignored by every program that loads the data. They are accepted in chip, fabric and workload files and inside a storage tier's mapping; they are not accepted in model.yaml or at the top level of devices/storage.yaml.
    • Each key has one unit. The tables below give it. Storage-tier keys spell their units out (_mb_s, _us). MB, GB and TB are decimal; GiB is 230 bytes.

    Models¶

    A model entry is the directory models/<name>/, holding three files.

    config.json
    The vendor's config, copied byte for byte. The validator checks only that it is a non-empty JSON object; the deriver interprets its keys. It is a third-party file under the licence model.yaml names: NOTICE says so, and licences/index.yaml names the licence text, under licences/, that travels with each file whose licence is not Apache-2.0.
    model.yaml

    Which model this is and where the config came from.

    Key Required Meaning
    name yes the entry's name; must equal the directory name
    source.provider yes where the config is hosted; huggingface for every entry
    source.repo yes the repository on that host, with its original capitalization
    source.revision yes the full commit hash the config was taken from
    source.retrieved no the date it was taken, YYYY-MM-DD
    licence.id yes the licence's SPDX identifier, or LicenseRef-<name> for a licence SPDX does not list
    licence.evidence yes the URL the licence was read from, at source.revision
    config.sha256 no the hash of a config.json that is not committed, because its licence is not on the allow-list
    graph.yaml
    The model graph, generated by scripts/derive_graph.py; never edited by hand. Model graphs explains its structure, and contracts/spec/model/graph.go defines it.

    Chips¶

    hardware/<name>.yaml, one chip per file. Figures are nominal and per GPU.

    Key Unit Required Meaning
    Provenance yes vendor_spec or derived; see Provenance
    TFlopsPeak TFLOP/s yes dense BF16 peak; positive
    TFlopsFP8 TFLOP/s always written dense FP8 peak; 0 on a chip without native FP8, otherwise greater than TFlopsPeak
    TFlopsNVFP4 TFLOP/s no dense NVFP4 peak; omitted where the format is not native
    BwPeakTBs TB/s yes HBM bandwidth; positive
    MemoryGiB GiB yes device memory, positive: the total the CUDA driver reports (what vLLM's gpu_memory_utilization multiplies) where a public log or NVIDIA device dump states it (h100, h200, b200, b300, gb200-nvl72, gb300, each cited in _comment_memory), otherwise the datasheet HBM capacity
    IntraNodeBwGBps GB/s yes intra-node link (NVLink where present), one direction; positive
    SMCount count yes streaming multiprocessors enabled on this chip; positive
    GPUsPerNode count no GPUs in one node; stated only for rack-scale chips
    GPUsPerRack count no GPUs in one rack-scale NVLink domain; when both are given, a multiple of GPUsPerNode
    IntraRackBwGBps GB/s no bandwidth between nodes in the rack, one direction; requires GPUsPerRack

    Always written means the schema would accept the key's absence, but every entry writes it, even where its value is 0. A missing key and a 0 decode alike; writing the 0 records that the chip lacks the format.

    Fabrics¶

    networks/<name>.yaml, one fabric class per file.

    Key Unit Required Meaning
    Provenance yes as for a chip
    InterNodeBwGBps GB/s yes nominal bandwidth per GPU, one direction: the line rate of the network cards serving one GPU, in GB/s; positive
    RDMA no true when the fabric moves data without passing it through the CPU

    Workloads¶

    workloads/<name>.yaml, one workload per file, in one of two forms. A file whose top-level key is replay: is a replay workload; any other is a shape, below. All values in a shape are tokens per request.

    Key Required Meaning
    prefix_tokens no length of the prefix requests share; 0, the default, means none; not negative, and at most prompt.tokens
    prompt.tokens yes mean prompt length; at least 1
    prompt.tokens_stdev no standard deviation; not negative
    prompt.tokens_min, prompt.tokens_max no bounds; the mean lies between those given
    output.* the same four keys, for the output

    Replay workloads¶

    A replay workload states, under replay:, a trace-replay scenario that the ReplayDefinition type of contracts/spec/workload defines: scenario, harness_version, a corpus (loader, format, encoding, source.huggingface, source.revision, and optionally source.file, source.split and sha256), and the scenario's settings (random_seed, benchmark_duration_s, grace_period_s, max_context_length, the keys the scenario locks, and the acceptance selectors category and thinking). It states no concurrency: a scenario that binds the workload states it. Comment keys are accepted at the top level only. The schema refuses any value the harness's own scenario validator would refuse, such as a duration below 900 s for inferencex-agentx-mvp.

    Storage tiers¶

    devices/storage.yaml, one file holding every tier, keyed by tier name. A tier is a name and a _comment description; it states no number. Its read rate, write rate and fixed cost per transfer are fitted or assumed, so they are registry coefficients (offload_tier_<tier>_read_rate, _write_rate and _base_latency), not catalog facts. A tier that states read_bandwidth_mb_s, write_bandwidth_mb_s or base_latency_us is refused.

    Measured runs¶

    measurements/sources.yaml is the licence registry: one entry per source a run may cite, with its status (verified, unverified or refused), the uses its terms permit (score, derive_coefficients, redistribute; none unless verified) and quoted evidence. measurements/<license_ref>/<name>.yaml is one measured run, a MeasuredRun of contracts/spec/measurement: its source and every input's sha256, the measured model, engine version, cluster, deployment and workload where stated, metric definitions, load-ordered points, provenance rows and differences. Its verdict is recomputed by the gate and must match. A committed run must cite a source that permits redistribute. These are third-party measurements recorded with their provenance; nothing here is fitted.
